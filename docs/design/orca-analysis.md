## 1. 한 줄 요약

Orca의 디자인 정체성은 **"단색이고 조용하다"**다. 회색이 화면 틀을 맡고, 색은 상태(선택 링, 위험, git 표시, 에이전트 상태)에만 쓴다.
Orca 화면 대부분은 다른 도구(터미널, 에디터, 채팅)를 담는 틀이다. 그래서 틀은 물러나고 내용이 앞에 선다.

우리 앱과 가장 크게 다른 점은 세 가지다.

| | Orca | Agent Workbench(지금) |
|---|---|---|
| 강조색 | 없음. 주요 버튼은 거의 흰색(`#e5e5e5`), 색은 상태에만 | 파란 강조색 `#5b8cff`를 버튼·포커스·선택에 사용 |
| 구조 | React + Tailwind v4 + shadcn/Radix 부품, 규칙 문서와 lint로 강제 | 바닐라 JS + CSS 한 파일(`styles.css` 1,052줄) |
| 화면 틀 | 제목줄 안에 탭, 좌 280px·우 350px 사이드바, 하단 24px 상태줄 | 상단 35px 바 + 37px 활동줄 + 176~224px 작업공간 + 216~320px 결과 패널 |

## 2. 디자인 토큰(다크 테마 기준)

### 2.1 색

shadcn의 역할 이름을 그대로 쓴다. **면(surface)과 그 위 글자(foreground)를 짝으로** 정의하고 항상 같이 쓴다.

| 역할 | 값 | 쓰는 곳 |
|---|---|---|
| `background` | `#0a0a0a` | 앱 바탕 |
| `card` | `#171717` | 바탕에서 한 단 올라온 패널, 탭 줄 |
| `popover` | `#171717` | 떠 있는 메뉴 |
| `editor-surface` | `#1e1e1e` | 에디터·마크다운 칸(앱 틀에는 쓰지 않음) |
| `foreground` | `#f0f0f0` | 본문 글자 |
| `primary` / `-foreground` | `#e5e5e5` / `#171717` | 흐름마다 **하나뿐인** 확정 버튼. 장식·hover에 쓰지 않음 |
| `secondary` | `#262626` | 확정 버튼 옆의 낮은 단계 버튼 |
| `muted` / `-foreground` | `#262626` / `#acacac` | 설명·캡션·placeholder·비활성 |
| `accent` | `#404040` | ghost 버튼과 목록 줄의 hover·현재 줄 배경(색이 아니라 회색) |
| `border` | `rgb(255 255 255 / 0.07)` | 모든 구분선(반투명 흰색 7%) |
| `input` | `rgb(255 255 255 / 0.15)` | 입력칸 테두리·배경 |
| `ring` | `#737373` | 키보드 포커스 링(지속 장식 아님) |
| `sidebar` | `#171717` | 왼쪽 사이드바 |
| `sidebar-primary` | `#1447e6` | 사이드바 안의 유일한 파랑 |
| `floating-surface` | `rgba(0,0,0,.72)` | 떠 있는 판 뒤 |
| `dialog-surface` | `rgba(23,23,23,.96)` | 대화상자 |

**상태 색**(색은 여기에만 쓴다)

| 상태 | 값 |
|---|---|
| 읽지 않음, 터미널 위치 표시 | blue-400 |
| 에이전트 질문(입력 필요) | orange-500 / 글자 orange-300 |
| AI 동작 | violet-400 |
| 작업 상태: 진행 / 검토 / 완료 | `#d4a300` / `#16a34a` / `#c7a594` |
| 실패 | red-500 점 |
| 사용자가 멈춤 | `muted-foreground` 점(실패도 완료도 아닌 중립) |

**규칙**

- 컴포넌트 코드에 hex를 쓰지 않는다. 새 색은 `main.css`의 라이트·다크 양쪽에 토큰으로 넣고 쓴다.
- 옅은 색이 필요하면 `color-mix(in srgb, var(--token) N%, var(--background))`로 만든다. 새 hex를 만들지 않는다.
- 목록 줄: 평소 투명 → hover `bg-accent` → 현재 줄 `bg-accent` + `data-current="true"`. **"선택됨" 색을 따로 만들지 않는다.**
- git 표시 색은 git 상태에만 쓴다.

### 2.2 글자

| 항목 | 값 |
|---|---|
| 본문 글꼴 | `Geist`(가변, 앱에 포함) → `-apple-system` → `Segoe UI` |
| 고정폭 | `--font-mono`(경로, 코드, 터미널 주변, 글자 그대로인 값) |
| 아이콘 글꼴 | Symbols Nerd Font Mono(터미널 아이콘 글리프용, unicode-range로 사설 영역만) |
| 자간 | `body`에 `0.01em` 한 번만. 부품마다 바꾸지 않음 |
| 렌더링 | `-webkit-font-smoothing: antialiased` |

크기 단계: 14px 본문·기본 버튼 / 13px 사이드바 항목·빽빽한 줄 / 12px 보조 글자·경로 / 11px(`text-2xs`) 대문자 분류 이름·캡션 / 10px(`text-3xs`) 배지.
분류 이름은 11px, semibold, 대문자, `tracking-wider`(0.05em)다.

채팅은 따로 정한 단계만 쓴다(lint로 강제). 13px 읽는 글 전부(메시지, 도구 줄, 카드, 입력창) / 12px 라벨·시간 / 11px 캡션 / 10px 배지 / 12px 코드·diff·명령 출력. 줄 높이는 13px 글자에 20px이다.

> Geist에는 한글이 없다. 우리 앱에 옮기면 한글은 대체 글꼴이 맡는다. 굵기·높이를 맞추려면 Pretendard를 Geist 뒤에 두는 것이 가장 자연스럽다(기존 결정 대기 항목 2번과 같은 문제).

### 2.3 모서리와 높이(그림자)

- 기준 `--radius: 0.625rem`(10px). sm 6px · md 8px · lg 10px · xl 14px · 2xl 18px.
- 버튼·입력칸 `rounded-md`(8px), 카드 `rounded-xl`(14px), 배지 `rounded-full`.
- 높이는 **세 단계뿐**이다.
  1. `border` 한 줄 — 거의 모든 것
  2. `shadow-xs` + 테두리 — outline 버튼, 안에 박힌 카드
  3. `shadow-floating`(`0 10px 24px rgb(0 0 0/.18)`) — 팝오버처럼 화면 위로 뜨는 것만. 토스트·알림 카드는 `--notice-shadow`(`0 16px 40px -8px rgb(0 0 0/.28), 0 3px 8px rgb(0 0 0/.12)`)
- 더 띄우고 싶으면 그림자 대신 포커스 링을 쓰라고 정해 두었다.

### 2.4 버튼

| 변형 | 모양 | 용도 |
|---|---|---|
| `default` | 흰 바탕 검은 글자 | 흐름의 유일한 확정 동작 |
| `secondary` | `#262626` 바탕 | 확정 버튼 옆 |
| `outline` | 테두리 + 옅은 입력 바탕, `shadow-xs` | 도구줄·단독 동작 |
| `ghost` | 평소 투명, hover `accent/50` | 아이콘 버튼, 줄 안 동작 |
| `link` | 밑줄 | 문장 안 |
| `destructive` | 빨강 | 삭제·되돌릴 수 없는 것. **취소에는 절대 쓰지 않음** |

크기: 기본 36px · sm 32px · xs 24px · lg 40px, 아이콘 버튼 36/32/24/40px. 채팅 보내기 버튼은 32px 원형이다.
공통: `gap 8px`, 글자 14px medium, 아이콘 16px, 포커스 시 3px 링(`ring/50`), 비활성 투명도 50%. 버튼 크기는 그 줄 높이에 맞춘다(28px 도구줄에 36px 버튼을 넣지 않는다).

### 2.5 아이콘·툴팁·단축키

- 아이콘은 **lucide 하나만**, 기본 16px, 기본 선 굵기, 색은 글자색을 따른다. 빽빽한 줄 12~14px, 빈 화면 큰 아이콘만 28px 이상. 로딩은 `Loader2` 회전.
- 툴팁은 **이름이 안 보이는 아이콘 버튼에만** 쓴다. 위쪽, 4px 간격. 중요한 메시지를 툴팁에 넣지 않는다.
- 단축키는 항상 같은 칩 부품으로 표시하고 실제 바인딩과 일치해야 한다. Windows는 `Ctrl+`, Mac은 `⌘`. 취소·닫기 버튼에는 칩을 달지 않는다.
- 스크롤바는 세 종류(`scrollbar-sleek`, `scrollbar-editor`, 사이드바 전용)만 둔다.

| 메시지 아래 | 복사·분기·위로 가기 아이콘과 시각 |
| transcript 줄 hover | `accent/20`(아주 옅게) |
| 포커스 | 스크롤 칸에 잘리지 않게 안쪽 링 |

채팅 안의 글자색은 `chat-foreground`(88%), `-strong`(98%), `-faint`(83%) 세 단계를 섞어 만든다. 손으로 `text-foreground/85` 같은 투명도를 주지 않는다.

## 5. UX 규칙(Orca가 문서와 lint로 지키는 것)

1. **진행 중 피드백은 걸리는 시간에 맞춘다.** 0~100ms 아무것도, 100ms~1초 비활성만, 1~3초 비활성 + 회전 표시, 3초 넘거나 여러 단계면 단계 이름("복제 중…" → "설치 중…"). 비활성은 즉시, 보이는 로딩은 약 200ms 늦게.
2. **글자가 바뀔 자리를 미리 잡는다.** 라벨이 길어지는 버튼은 `width`로 크기를 고정한다. 동작 중에 크기가 바뀌면 고장 난 것처럼 보인다.
3. **문구는 과장하지 않는다.** 실제 결과가 있을 때만 "완료", "찾음", "삭제됨"을 쓴다. "please", "simply", "just" 같은 군더더기 금지.
4. **물러나는 길은 조용하게.** 취소·닫기·버리기는 ghost, 색 없음, 단축키 칩 없음. Esc는 동작한다.
5. **옆 부품과 맞춘다.** 같은 흐름에서 이웃한 부품은 아이콘·단축키·제출 방식이 같아야 한다.
6. **접는 화살표는 제목 앞에.** 펼침 ▾, 접힘 ▸. 모든 화살표가 한 열에 선다.
7. 확정 동작이 한눈에 보이고, 흔한 일은 1~2번 조작으로. 기본 포커스는 가장 가능성 높은 칸, Enter로 제출, Esc로 나가기.
8. **데이터가 없으면 그것을 얻는 버튼을 보여 준다.** 일시적 결과는 토스트, 읽고 다시 시도해야 하는 오류는 그 자리에 남긴다.
9. 움직임 줄이기 설정을 요소마다 지킨다.
10. 신뢰·승인·코드 실행을 묻는 대화상자는 `surface="security"` 전용 면을 써서 테마가 바꾸지 못하게 한다.

## 7. 우리 앱에 옮기는 계획

### 7.1 먼저 정할 것

1. **강조색을 버리고 Orca처럼 단색으로 갈지.**
   - 추천은 단색이다. 2.1의 값을 그대로 쓰고 파랑은 "읽지 않음·선택 링"에만 남긴다.
   - 1단계에서 넣은 파란 강조색(`--accent: #5b8cff`)을 되돌리는 결정이다.
2. **React + Tailwind로 옮길지, 지금 구조에서 CSS만 바꿀지.**
   - 추천은 CSS만 바꾸는 것이다. 토큰 이름을 shadcn 역할 이름(`background`, `card`, `primary`, `muted`, `accent`, `border`, `ring`)으로 바꾸고 2장의 값을 넣는다.
   - 디자인은 대부분 토큰·크기·규칙에서 나오므로 프레임워크 없이 90% 가까이 맞출 수 있다.
   - 화면 전체를 다시 쓰는 비용과 메모리 목표(가벼운 앱)를 생각하면 React 전환은 이득이 적다.
3. **글꼴:** Geist + Pretendard(한글)를 앱에 넣을지. 합쳐 약 2MB다.

### 7.2 단계

| 단계 | 내용 | 바뀌는 파일 |
|---|---|---|
| A. 토큰 교체 | 2.1~2.3 값으로 `:root` 교체. 역할 이름으로 바꾸고 옛 이름은 별칭으로 잠시 유지. 반투명 7% 구분선, radius 10px 체계, 그림자 3단계 | `styles.css` |
| B. 부품 | 버튼 6변형·4크기, 입력칸, 목록 줄(hover·current), 토스트(notice 면), 툴팁 규칙, 단축키 칩 하나로. 아이콘을 lucide SVG 스프라이트로 | `styles.css`, `index.html`, `panels.js` |
| C. 화면 틀 | 36px 제목줄에 탭 넣기, 왼쪽 280px(220~500) 사이드바에 이동 항목 + 프로젝트별 작업 카드, 오른쪽 350px 사이드바에 아이콘 탭(변경·파일·PR 체크), 24px 상태줄에 사용량 | `index.html`, `styles.css`, `workspace.js`, `renderer.js` |
| D. 작업 카드 | 3장의 2줄 카드와 12px 상태 표시 6종 | `workspace.js` |
| E. 채팅 | 46rem 본문, 사용자 메시지 옅은 면, 입력창 카드(+·권한·모델·원형 보내기), 아래 작업 폴더 줄, 메시지 아래 동작 아이콘 | `composer.js`, `styles.css` |
| F. 규칙 | 5장 UX 규칙을 `docs/STYLEGUIDE.md`로 옮겨 두고 이후 변경의 기준으로 사용 | 문서 |
| G. 기능 | 작은 것부터: 파일 탐색기(이름/내용, `rg` 사용) → 작업 바로가기(Ctrl+J) → 상태줄 사용량 상시 표시 | 새 모듈 |

A·B는 기능 변화 없이 화면 전체 인상이 바뀐다. C는 배치를 크게 바꾸므로 따로 PR로 낸다.

### 7.3 옮기지 않을 것

- 봇, 모바일 앱, 원격 서버, 클라우드 VM, 플러그인: 서버나 별도 앱이 필요하다. 우리 앱의 목표(PowerShell 결과 복사, 가벼운 메모리, 나만의 기능) 밖이다.
- Monaco 에디터: Orca 번들에서 가장 큰 덩어리(언어 워커 수 MB)다. 메모리 목표와 맞지 않는다.
- 12개 언어 번역: 한국어만 쓴다.
