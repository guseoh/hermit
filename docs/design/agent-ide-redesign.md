# Agent Workbench 재설계: UI/UX, 에이전트 자동 연결, 기능·최적화

작성: 2026-11-22 · 상태: 설계(구현 전) · 기준 코드: `main` d3ea99a

이 문서는 세 가지 요청에 대한 설계다.

1. UI/UX 전체 개선: 디자인이 딱딱하고 쓰기 불편하다. 버튼 하나까지 다시 본다.
2. Codex·Claude가 Orca나 Claude 앱처럼 자동으로 연결되고, Orca처럼 터미널과 채팅이 함께 있는 화면. 지금은 새 탭 메뉴에 Codex·Claude가 보이지 않는다.
3. 추가·확장할 기능과 최적화할 부분.

## 0. 지금 상태 진단

### 0.1 새 탭 메뉴에 Codex·Claude가 안 보이는 원인

- 두 항목은 `index.html`의 `#agent-launch-menu`에 있다. 그런데 채팅 설정의 **"채팅 UI 사용"이 기본으로 꺼져 있고**(`chatPreferences.enabled === false`), 이 값이 꺼져 있으면 메뉴 그룹 전체를 숨긴다(`workspace.js:1272`).
- 켜더라도 에이전트별 기본 실행 모드가 **"CLI"**(기본값)이면 `launchAgentFromMenu`가 에이전트가 아니라 **빈 PowerShell만 연다**(`workspace.js:1320-1323`). 사용자가 프롬프트에 `codex`를 직접 쳐야 한다.
- 즉, 기본 설정에서는 메뉴로 에이전트를 시작할 길이 없다. 처음 쓰는 사람은 설정 화면 두 곳을 바꿔야 한다.

### 0.2 에이전트 연결 구조

| 항목 | 지금 방식 | 문제 |
|---|---|---|
| 연결 시점 | 첫 메시지를 보낼 때 연결("요청을 보내면 연결합니다") | 첫 응답이 늦고, 연결 실패를 보내는 순간에야 안다 |
| Codex | 작업마다 `codex app-server` 프로세스 1개 | 작업 5개면 Codex 서버 프로세스 5개 + 각자의 node·codex.exe |
| Claude | **메시지마다** `claude -p` 프로세스를 새로 띄우고 `--resume`(`claude.cjs:17`) | 턴마다 2~5초 시작 비용, 세션 파일 재읽기 |
| 채팅 ↔ 터미널 | Codex만 "Codex 터미널"로 바꿀 수 있고, 채팅을 끊은 뒤 TUI를 `resume`. 돌아오려면 TUI에서 `/exit` | 둘 중 하나만 보인다. Claude는 전환 불가 |
| 에이전트 확인 | `agent-probe.ps1`을 프로필까지 읽으며 실행(약 9초) | 메뉴·연결·AI 메시지가 모두 이 대기를 탄다 |
| 사용량 | 조회할 때마다 Codex 서버를 새로 띄워 `account/rateLimits/read` | 프로세스 하나를 통째로 띄웠다 끈다 |

### 0.3 디자인

- 강조색이 회색(`--accent: #c5c5c5`)이다. 주요 버튼과 일반 버튼이 구분되지 않고, 누를 곳이 보이지 않는다.
- 모서리가 모두 직각이다(`border-radius:0` 32곳). 카드·입력칸·버튼이 같은 상자처럼 보여 위계가 없다.
- 아이콘이 `◫ ⑂ ›_ ⚙ ＋ ↻ ⤢ ▦` 같은 글자 기호다. 굵기·크기·정렬이 제각각이고, 글꼴에 따라 깨진다.
- 한글 글꼴을 지정하지 않았다(`"Segoe UI", sans-serif`). Segoe UI에는 한글이 없어 맑은 고딕으로 대체되며 영문과 한글의 굵기와 높이가 맞지 않는다.
- 같은 요소를 두 번 정의한 스타일이 많다(`.change-file` 528·781행, `.patch-row` 554·791행 등). 기능을 덧붙이며 쌓인 것이라 고칠 때마다 어긋난다.
- 상태·오류를 하단 `#status` 한 줄 글자로만 알린다. 잘 안 보이고 금방 덮인다.
- 빈 화면(첫 실행, 작업 없음, Git 아님)에 다음 행동 안내가 없다. 스크린샷의 "Git 저장소가 아닙니다"가 그렇다.

### 0.4 성능

| 위치 | 하는 일 | 비용 |
|---|---|---|
| `workspace.js:2168` | 3.5초마다 `git status` + `diff --numstat` 2번 | 작업 폴더가 커지면 CPU·디스크 지속 사용 |
| `renderer.js:26` | 1초마다 localStorage 전체를 JSON으로 만들어 비교 | 메모·노트가 많으면 매초 수 MB 직렬화 |
| `renderer.js:762` | xterm을 DOM 렌더러로, 터미널마다 스크롤백 2만 줄 | 출력이 많은 터미널에서 프레임 저하, 메모리 증가 |
| 사용량 조회 | Codex 서버 프로세스 새로 띄움 | 조회마다 수백 MB급 프로세스 시작 |
| 리소스 표시 | PowerShell + `Get-CimInstance`로 전체 프로세스 조회 | 조회마다 PowerShell 시작(0.5~1초 CPU) |
| `workspace.js` | 2,300줄 전역 스크립트 한 파일 | 고칠 때 영향 범위를 알기 어렵고, 화면 전체를 다시 그리는 경로가 많다 |

## 1. UI/UX 재설계

### 1.1 원칙

1. **할 일이 먼저 보인다.** 화면마다 주요 행동은 하나이고, 그것만 강조색이다.
2. **상태는 색과 모양으로 한눈에 보인다.** 작업 중·승인 대기·완료·실패를 점·배지·배너로 일관되게 보여 준다.
3. **에이전트가 기본, 터미널은 언제나 옆에.** 에이전트 작업이 중심이고, 같은 폴더의 터미널이 바로 아래에 붙어 있다(Orca 방식).
4. **키보드로 다 된다.** 모든 동작은 명령 팔레트와 단축키로 닿는다. 마우스는 보조다.
5. **조용하게.** 장식선과 테두리를 줄이고, 면(배경 단계)과 여백으로 구역을 나눈다.

### 1.3 공통 컴포넌트

지금은 화면마다 버튼과 입력칸을 따로 꾸민다. 아래 컴포넌트를 CSS 클래스와 작은 JS 도우미로 만들고, 모든 화면이 이것만 쓴다.

| 컴포넌트 | 규칙 |
|---|---|
| Button | `primary`(강조색, 화면에 하나), `secondary`(면), `ghost`(배경 없음), `danger`. 크기 `sm` 24px / `md` 30px. 진행 중이면 스피너와 함께 비활성 |
| IconButton | 정사각형, 툴팁 필수, `aria-label` 필수. 아이콘은 1.3 아이콘 세트만 쓴다 |
| Input·Textarea·Select | `--bg-3`, `--r-md`, 포커스 시 강조색 테두리 2px |
| Switch·Checkbox | 설정은 Switch, 목록 선택은 Checkbox |
| Tabs | 밑줄형(본문), 알약형(필터) 두 가지 |
| StatusDot·Badge | 작업 상태 5종(작업 중·승인 대기·완료·실패·대기). 점 + 색 + 모양(●, !, ✓, ✕)으로 색약도 구분 |
| Card | 채팅의 도구 실행, 파일 변경, 승인, 리뷰 노트, PR 피드백 |
| Banner | info·warn·error·success. 행동 버튼 최대 2개 |
| Toast | 하단 `#status` 글자를 대체. 3~5초, 오류는 닫을 때까지, "실행 취소" 버튼 가능 |
| Dialog·Popover·Menu | 하나의 구현으로 통일. 바깥 클릭·Esc로 닫힘, 포커스 가두기 |
| EmptyState | 아이콘 + 한 줄 설명 + 주요 행동 버튼 하나 |
| Kbd | 단축키 표시 |

**아이콘:** 글자 기호를 모두 SVG 아이콘으로 바꾼다. [Lucide](https://lucide.dev)(ISC 라이선스)에서 쓰는 것만 골라 `assets/icons.svg` 스프라이트 하나로 묶고 `<svg><use href="#i-git-branch"/></svg>`로 쓴다. 16px, 선 굵기 1.5로 통일한다. `panels.js`의 `setPanelIcon`이 이미 SVG를 쓰므로 그 방식을 넓힌다.

- **왼쪽(프로젝트):** 프로젝트 → 작업(=worktree) 2단. 작업 행에는 상태 점, 이름, 브랜치(마우스를 올리면), PR 배지, 변경 줄 수를 둔다. "닫은 작업"은 접힌 묶음으로 둔다.

- **오른쪽(검토):** 변경사항, PR, 리뷰 노트, 플래너를 탭으로 둔다. 접을 수 있다.
- **상태 표시줄:** 에이전트 준비 상태, 사용량, 알림·절전 설정을 둔다.
- 창 폭이 960px보다 좁으면 오른쪽 검토 패널이 덮개(overlay)로 바뀌고, 1280px보다 좁으면 왼쪽이 아이콘 줄로 접힌다.

### 1.5 새 작업 시작 흐름

지금은 "새 탭" 메뉴(터미널 중심)와 "새 작업" 창(에이전트)이 나뉘어 있고, 에이전트는 기본 설정에서 숨겨져 있다. 이것을 하나의 **실행기**로 합친다.

```
┌ 새로 열기 ─────────────────────────────── Ctrl+N ┐
│ [무엇을 할까요? 작업 이름이나 요청을 입력…      ] │
│                                                  │
│ 에이전트                                          │
│  ◉ Codex        채팅 · 터미널     준비됨          │
│  ✳ Claude Code  채팅 · 터미널     로그인 필요 →   │
│   폴더: my-app ▾   ☑ 새 브랜치·worktree           │
│                                                  │
│ 그 밖에                                          │
│  ›_ PowerShell 5.1                    Ctrl+T     │
│  📝 Markdown 노트  ·  🌐 웹 미리보기  ·  ▤ 플래너  │
└──────────────────────────────────────────────────┘
```

- 에이전트 항목은 **항상 보인다**. "채팅 UI 사용" 설정은 없앤다.
- 항목마다 채팅과 터미널을 고르는 작은 버튼이 있다. 기본값(마지막 선택)은 굵게 표시하고 Enter로 바로 연다.
- 입력칸에 쓴 글은 작업 이름과 **첫 요청**이 된다. 열자마자 에이전트가 시작한다(2장 자동 연결).
- CLI가 없거나 로그인이 필요하면 그 자리에 "설치 안내"와 "로그인" 버튼을 보여 준다.
- "터미널"을 고르면 빈 PowerShell이 아니라 **에이전트 TUI가 실행된 터미널**을 연다.

### 1.6 채팅 화면 세부

- **입력창:** 내용에 따라 1~10줄로 자란다. Enter 보내기 / Shift+Enter 줄바꿈(설정으로 바꿀 수 있음). 보내기 버튼은 실행 중이면 중단 버튼으로 바뀐다.
- `@`로 파일 자동완성(작업 폴더의 `git ls-files`), `/`로 명령(모델 바꾸기, 압축, 새 대화, 터미널로 열기), 이미지 붙여넣기.
- 에이전트가 일하는 동안 보낸 메시지는 **대기열**에 칩으로 쌓였다가 턴이 끝나면 순서대로 보낸다.
- **메시지:** 내 메시지는 오른쪽 말풍선. 에이전트 답은 마크다운(코드 블록 복사 버튼, 언어 표시)이다.
- **도구 실행:** 한 줄 카드(아이콘·명령·걸린 시간·성공/실패)로 보여 주고, 펼치면 출력이 나온다. 연속된 읽기 작업은 "파일 5개 읽음"처럼 하나로 묶는다.
- **파일 변경:** 카드에 파일 목록과 +/− 줄 수를 보여 준다. "diff 보기"를 누르면 오른쪽 검토 패널이 그 파일로 열린다.
- **승인 요청:** 강조 테두리 카드에 명령·이유와 [허용]/[거부]/[이 세션 동안 허용]을 둔다. 작업 탭과 왼쪽 목록에는 `!` 표시가 붙는다.
- **턴 끝:** 걸린 시간, 토큰·비용, "이 턴 되돌리기"(3장의 체크포인트)를 보여 준다.

### 1.7 버튼·문구 단위 정리(예시)

| 지금 | 바꿈 | 이유 |
|---|---|---|
| `＋` (새 탭) | `+` 아이콘 + 툴팁 "새로 열기 (Ctrl+N)" | 전각 기호 대신 아이콘 |
| "연결" / "연결 종료" 버튼 | 없앰(자동 연결). 상태 칩 "준비됨·재연결 중"과 메뉴의 "세션 다시 시작" | 연결은 앱이 알아서 한다 |

### 1.8 접근성·움직임

- 모든 아이콘 버튼에 `aria-label`과 툴팁을 단다. 포커스 테두리는 항상 보이게(`:focus-visible`) 한다.
- 대비는 본문 4.5:1 이상(토큰 값으로 보장)으로 한다.
- 패널 열기·닫기, 카드 펼치기는 120~180ms로 움직인다. `prefers-reduced-motion`이면 움직임을 끈다.

## 2. 에이전트 자동 연결과 터미널·채팅 구조

### 2.1 목표

- 작업을 만들거나 선택하면 **에이전트가 이미 준비돼 있다**. 사용자는 연결을 신경 쓰지 않는다(Claude 앱의 Code 탭 방식).
- 한 작업 = worktree 하나 + 에이전트 세션 하나 + 그 폴더의 터미널 묶음(Orca 방식).
- 같은 세션을 **채팅으로도, 터미널 TUI로도** 볼 수 있고, 두 에이전트에 똑같이 적용된다.

### 2.2 메인 프로세스: AgentHost

`main.cjs`에 흩어진 `conversations` 관리를 `agent-host.cjs`로 모은다.

```
AgentHost
 ├─ CodexServer (앱 전체에 1개)        codex app-server --stdio
 │    └─ thread ↔ task 연결표           thread/start, thread/resume, turn/start …
 ├─ ClaudeSession (작업마다 1개, 지속)   claude -p --input-format stream-json … (stdin을 열어 둠)
 ├─ SessionState (작업마다)              idle → starting → ready → running → waiting → ready …
 │                                       ↘ error(재시도 대기) ↘ suspended(유휴로 내림)
 ├─ 이벤트 정규화                         두 에이전트를 같은 이벤트 모양으로 렌더러에 보냄
 └─ 상태 감지(TUI 모드)                   Claude hooks · Codex notify → 이름 있는 파이프
```

**Codex: 서버 1개로 모든 작업을 다룬다.** app-server는 한 연결에서 여러 thread를 다룰 수 있다. 작업마다 프로세스를 띄우지 않고, 서버 하나에서 `thread/start`·`thread/resume`으로 작업별 thread를 연다. 이벤트는 `threadId`로 작업에 나눠 보낸다. 사용량(`account/rateLimits/read`)도 이 서버에 물어서, 조회용 프로세스를 따로 띄우지 않는다.

- 주의: thread마다 `cwd`가 다르므로 `thread/start`에 작업 worktree 경로를 넘긴다(지금도 넘긴다). 서버의 시작 폴더는 사용자 홈으로 둔다.
- 서버가 죽으면 열려 있던 thread를 모두 `thread/resume`으로 다시 붙인다.

**Claude: 작업마다 프로세스 하나를 계속 띄워 둔다.** `--input-format stream-json`은 stdin으로 사용자 메시지를 여러 번 받을 수 있다. 턴마다 새로 띄우지 않고 프로세스를 유지해 시작 비용(2~5초)을 없앤다. 유휴 시간(기본 15분)이 지나면 내리고, 다음 메시지 때 `--resume <sessionId>`로 다시 띄운다. 사용자는 이것을 느끼지 못한다.

- 모델·추론 수준을 바꾸면 그 턴에서 `--model`·`--effort`로 다시 띄우거나, 지원하는 제어 요청(`control_request`)으로 바꾼다.

**자동 연결 규칙**

| 사건 | 동작 |
|---|---|
| 앱 시작 | CLI 확인(캐시 사용, 2.5) → 마지막으로 보던 작업만 미리 준비(prewarm) |
| 작업 만들기 | 바로 세션 시작. 첫 요청이 있으면 준비되는 대로 보냄 |
| 작업 선택 | 내려가 있으면(suspended) 다시 붙임. 화면에 바로 "준비 중" 표시 |
| 세션 오류·종료 | 1초 → 2초 → 5초 → 15초 간격으로 다시 시도. 3번 실패하면 배너와 [다시 시도] |
| 로그인 필요 | 오류가 아니라 "로그인 필요" 상태. 배너에서 [로그인]을 누르면 로그인 터미널 |
| 유휴 15분 | Claude 프로세스를 내림(suspended). Codex thread는 서버에 남김 |
| 작업 닫기 | 세션 종료. worktree 정리는 지금처럼 따로 묻는다 |

### 2.3 렌더러: 작업 화면 = 채팅 + 작업 터미널

- `runtime(task)`의 `connected`·`connecting`·`terminalMode`를 **`session.state` 하나**로 바꾼다(위 상태 머신). 버튼·배지·상태 표시줄은 모두 이 값만 본다.
- **작업 터미널 묶음:** 작업마다 `terminalGroup`을 둔다. 작업을 선택하면 가운데 아래 터미널 영역이 그 작업의 묶음으로 바뀐다. 묶음은 필요할 때 만든다(처음 열 때 셸 1개).
  - 터미널 탭 종류: **셸**(worktree에서 PowerShell), **실행 프로필**(개발 서버·테스트), **에이전트 TUI**.
  - `package.json`의 `scripts`, `Makefile` 등을 읽어 실행 프로필 후보를 제안한다(기존 "실행 프로필" 기능 확장).

### 2.4 채팅 ↔ 터미널 전환

같은 대화를 두 화면에서 동시에 조작하면 충돌하므로, **한 번에 한쪽만 조작**하되 전환을 매끄럽게 한다.

```
[채팅 보기] ──"터미널로 열기"──▶ 채팅 세션 일시 정지(프로세스 유지 안 함)
     ▲                              에이전트 TUI 탭: codex resume <threadId> / claude --resume <sessionId>
     │                              상태는 TUI 상태 감지(2.6)로 계속 표시
     └──── TUI 종료(/exit, 탭 닫기) 감지 ◀── 자동으로 채팅 세션 다시 붙이고 그동안의 대화를 불러옴
```

- 작업 머리줄의 `[채팅 | 터미널]` 전환 하나로 두 에이전트를 똑같이 다룬다. 지금은 Codex만 되고 Claude는 안 된다.
- 터미널에서 돌아오면 Codex는 `thread/turns/list`, Claude는 세션 기록으로 그사이 대화를 채팅에 채운다.
- TUI가 실행 중인 동안 채팅 입력창은 "터미널에서 진행 중 · [채팅으로 돌아가기]"로 바뀐다.

### 2.5 CLI 확인(probe) 개선

- 메인 프로세스가 앱 시작 때 한 번 확인하고, 결과를 `userData/agents.json`에 **실행 파일 경로와 수정 시각**으로 저장한다. 다음 시작 때는 파일이 그대로면 확인을 건너뛴다.
- `agent-probe.ps1`은 `-NoProfile`로 실행하고, PATH는 레지스트리의 사용자·시스템 PATH를 합쳐 쓴다. 프로필을 읽어 9초씩 걸리던 것이 1초 안팎이 된다.
- 설정의 "에이전트" 탭에서 [다시 찾기]와 실행 파일 직접 지정을 할 수 있다.

### 2.6 TUI 모드에서 상태 알기(Orca 방식)

에이전트를 터미널에서 직접 돌려도 작업 목록의 상태 점과 알림이 동작해야 한다.

- **Claude Code:** 작업을 열 때 worktree의 `.claude/settings.local.json`에 hooks(`Notification`, `Stop`, `UserPromptSubmit`)를 넣는다. hook은 작은 스크립트로 앱의 이름 있는 파이프(`\\.\pipe\agent-workbench-<id>`)에 상태를 보낸다. 넣은 항목은 표시해 두고 작업을 정리할 때 지운다.
- **Codex:** `-c notify=[...]` 설정으로 턴 완료 알림을 같은 파이프로 받는다.
- 보조 수단: 터미널 출력의 OSC 제목·벨(BEL)과 프롬프트 표식(`prompt.ps1`의 `workbench-prompt`)으로 "입력 대기"를 짐작한다.

### 2.7 렌더러에 보내는 이벤트(정규화)

```
session/state      { taskId, state, reason? }          준비·실행·대기·오류 …
turn/started       { taskId, turnId }
item/started|delta|completed { taskId, item }          userMessage, agentMessage, command, fileChange, plan, reasoning
approval/request   { taskId, id, kind, command?, files?, reason }
turn/completed     { taskId, turnId, status, usage, durationMs, checkpoint? }
usage/updated      { provider, limits }
```

- 렌더러는 provider를 거의 몰라도 된다. 지금 `claude.cjs`가 Codex 모양으로 맞춰 보내는 방식을 넓힌다.
- 메시지 내용은 작업별 저장소(`userData/sessions/<taskId>.jsonl`)에 이어 쓴다. 앱을 다시 켜면 렌더러는 마지막 100개만 받고, 위로 스크롤할 때 더 받는다.

### 2.8 보안

지금 방식(IPC 발신자 검사, 입력 검증, sandbox, CSP)을 그대로 유지한다.

- 새 IPC도 `handle()`을 거치고, 렌더러가 보낸 경로·명령은 메인에서 다시 검사한다.
- hooks 파이프는 작업별 무작위 이름과 일회용 토큰으로 다른 프로세스가 끼어들지 못하게 한다.
- "이 세션 동안 허용"은 메모리에만 두고, 앱을 다시 켜면 사라진다.

## 5. 코드 구조 정리(구현을 위한 바탕)

```
main/
  main.cjs            창, IPC 등록(handle)만
  agent-host.cjs      2장의 AgentHost (codex-server.cjs, claude-session.cjs 사용)
  terminals.cjs       node-pty 관리, 작업별 묶음
  git.cjs             지금의 changes.cjs (status·diff·worktree·commit·PR)
  github.cjs          gh 호출, PR 피드백
  state.cjs, notify.cjs
renderer/
  app.js              시작, 전역 상태 저장소(작은 store + 구독)
  ui/                 1.3 컴포넌트: button, dialog, toast, menu, icons …
  views/              sidebar, task-header, chat, composer, terminal-area, review/, settings/
  lib/                pr-feedback.js, review-notes.js, markdown.js, keybindings.js
styles/
  tokens.css  components.css  layout.css  views/*.css
```

- 번들러 없이 ES 모듈(`<script type="module">`)로 나눈다. CSP `script-src 'self'`를 그대로 지킬 수 있다.
- 화면 상태는 store 하나에 두고, 화면 조각은 필요한 값만 구독해 다시 그린다. 지금처럼 `renderChat()`가 전체를 다시 그리지 않는다.
- 이미 테스트가 있는 순수 모듈(`pr-feedback.js`, `review-notes.js`, `state.cjs`)과 같은 방식으로 store와 이벤트 정규화를 테스트한다.

### 먼저 확인할 가정

설계가 기대는 동작 중 아직 이 앱에서 시험하지 않은 것이다. 2단계를 시작하기 전에 작은 시험 코드로 확인하고, 안 되면 대안으로 간다.

| 가정 | 안 될 때 대안 |
|---|---|
| `codex app-server` 연결 하나에서 cwd가 다른 thread 여러 개를 동시에 돌릴 수 있다 | 서버를 저장소(프로젝트)별로 1개 |
| `claude -p --input-format stream-json` 프로세스가 stdin으로 여러 턴을 받는다(지금 코드는 턴마다 새로 띄움) | 지금 방식 유지 + 다음 턴용 프로세스를 미리 띄워 두기 |
| Claude Code hooks와 Codex `notify`로 TUI 상태를 받을 수 있다 | 터미널 출력(OSC 제목·BEL·프롬프트 표식)으로만 짐작 |
| `fs.watch(recursive)`가 큰 저장소에서도 안정적이다 | `.git/index`·`HEAD`만 감시 + 창이 보일 때 10초 주기 확인 |

### 결정이 필요한 것

1. **강조색:** 파랑(#5b8cff, 기본안) / 보라 / 주황(Claude 색) 중 하나.
2. **한글 글꼴:** Pretendard를 앱에 넣을지(약 1.5MB), 시스템 맑은 고딕만 쓸지.
3. **Claude 지속 세션의 유휴 시간:** 기본 15분안. 메모리를 아끼려면 더 짧게.
4. **TUI 상태 감지의 hooks:** worktree의 `.claude/settings.local.json`에 자동으로 넣어도 되는지(넣은 항목은 표시하고 정리할 때 지움).
5. **모듈 나누기(5장)를 언제 할지:** 1단계 전에 먼저 하면 이후 작업이 쉬워지지만, 눈에 보이는 변화가 늦어진다.
